# DELT-Hit Benchmark Configuration

DELT-Hit uses cutadapt internally for demultiplexing. Each dataset has a
`config.yaml` that defines the experiment, sequence structure, and per-segment
error rates.

## Specifying the Error Rate (`max_error_rate`)

Each segment in the `structure` list has a `max_error_rate` field, passed
directly to cutadapt. The value is interpreted differently depending on whether
it is a float or an integer:

| Value type | Interpretation | Example |
|------------|----------------|---------|
| **float** `0 < v < 1` | Maximum error rate as a **fraction** of the matched region length. `0.1` = at most 10% of the matched bases can be errors. Actual budget = ⌊rate × length⌋, so the effective error count varies with codon length. | `max_error_rate: 0.1` on an 8-mer → 0 errors; on a 10-mer → 1 error. |
| **int** `≥ 1` | **Absolute** number of allowed errors, converted internally to a per-adapter rate (`errors / adapter_length`). Unambiguous regardless of codon length. | `max_error_rate: 1` always allows exactly 1 error. |

> **Benchmarks use integers** — they are unambiguous and don't require
> knowing the codon length to interpret. Avoid floats unless you specifically
> want length-proportional tolerance.

### Values used in benchmarks

`config.yaml` files are generated by `benchmarks/demultiplex/converter/create_delt_inputs.py`,
which writes `num_errors` from the dataset manifest directly as the integer
`max_error_rate` for all segments except the UMI.

| Dataset suffix | Segment type | `max_error_rate` | Effective errors |
|----------------|-------------|------------------|-----------------|
| `err=0` | all segments | `0` | 0 |
| `err=1` | selection (`S0`), building blocks (`B0–B3`), constant (`C0`) | `1` | 1 |
| `err=1` | UMI (`U0`) | `0` | 0 (UMI is not error-corrected) |

### `indels`
When `false` (default in benchmarks), only substitutions are counted toward
`max_error_rate`. Set to `true` to also allow insertions and deletions.
