Creation of the configuration file defining library structure, experimental design and analysis parameters from a standardized Excel template.

\protocolstep{Phase 2}{Sequence processing and demultiplexing • TIMING 30 min - 4
h}
Processing of raw sequencing reads to identify and count library members in the analyzed selection experiments.

\protocolstep{Phase 3}{Data visualization and interpretation • TIMING 15-60 min}
Exploration of count data and experimental metadata using the interactive dashboard.

\protocolstep{Phase 4}{Selection-centric enumeration and analysis • TIMING 10 min
- 2 h}
Analysis of top enriched compounds. Chemical structures and molecular properties are generated for a subset of highly enriched compounds for individual selection experiments.

\protocolstep{Phase 5}{Statistical analysis and hit identification • TIMING 10-30 min}
Statistical identification of enriched library members based on comparison of different selection experiments.

• TIMING 1 h - 8 h}
In-silico chemical assembly of all library members and calculation of molecular property distributions. This step is independent of phases 2-5 and can also be performed without sequencing data, for instance for evaluating library designs prior to DEL synthesis.

\subsection{Phase 1: Project initialization and configuration • TIMING 30-60 min}
The configuration file defines library structure, experimental design, and analysis parameters. DELT-Hit initializes this file from a standardized Excel template, a rudimentary template file can be found in the supplementary information.

In this phase, a YAML configuration file is created from an Excel workbook that contains the DEL library and experimental design information.


\protocolstep{1}{Create the experiment sheet}

Create an Excel workbook with multiple sheets defining the experiment. Each sheet contains specific information required for the analysis. The following sections describe the required sheets and their format. Users can start from the template provided in Table 3. The experiment sheet contains the experiment name, file paths, and computational resource settings.


\input{tables/experiment-config}

\protocolstep{2}{Create the selection sheet}

This sheet defines the experimental design, including selection conditions, multiplexing barcodes, and replicate grouping. Each row describes one experimental setting, such as a target protein or control condition, and is identified by a unique combination of \texttt{S0} and \texttt{S1} primers for demultiplexing.


\input{tables/selection-design}
Required columns for demultiplexing:

\begin{itemize}
  \item name: Unique identifier for each selection
  \item S0, S1: Multiplexing barcodes for selection identification
\end{itemize}
Required columns for statistical analysis:

\begin{itemize}
  \item group: Statistical grouping (e.g., "protein", "no\_protein", "naive")
\end{itemize}
Optional columns:

\begin{itemize}
  \item operator: Person who performed the selection
  \item date: Date of selection experiment
  \item other columns can be added at the user's discretion
\end{itemize}

\protocolstep{3}{Create the structure sheet}

This sheet defines the DNA construct architecture and error tolerances for demultiplexing.

There are three types of DNA regions:

\begin{itemize}
  \item \texttt{selection}: Region used for selection primers defined in the selection sheet; these regions should be named \texttt{S0}, \texttt{S1}, and so on.
  \item \texttt{constant}: Constant regions shared across DNA constructs; these regions should be named sequentially \texttt{C0}, \texttt{C1}, and so on.
  \item \texttt{building\_block}: Region identifying a chemical building block; these regions should be named sequentially \texttt{B0}, \texttt{B1}, and so on.
\end{itemize}
Each DNA region is identified by a unique name. A \texttt{max\_error\_rate} and the allowance of indels can be configured separately for each region.


\input{tables/sequence-structure}
Column descriptions:

\begin{itemize}
  \item name: Unique identifier for each DNA region
  \item type: Region type (selection, constant, or building\_block)
  \item max\_error\_rate: Maximum allowed error rate for adapter trimming (0 = perfect match, 0.1 = \textasciitilde{}10\% errors)
  \item indels: Whether to allow insertions/deletions (TRUE/FALSE)
\end{itemize}
CRITICAL STEP: Selection barcodes should require perfect matches (\texttt{max\_error\_rate = 0}, \texttt{indels = FALSE}) to ensure accurate multiplexing. Constant regions can tolerate higher error rates depending on their length.

This sheet contains the DNA sequences for all constant regions defined in the structure sheet.

\protocolstep{5}{Create building block sheets (B0, B1, etc.)}

DELT-Hit supports libraries with an arbitrary number of building block regions. For each region defined in the structure sheet, create a sheet with the corresponding name (for example, \texttt{B0}, \texttt{B1}, ..., \texttt{BN}) and list the DNA codons used at that position. To enable library enumeration and property calculation, also define the chemical structures of the building blocks and the reactions used during library synthesis.


\input{tables/building-blocks-b0}

\begin{itemize}
  \item codon: DNA barcode sequence identifying this building block
\end{itemize}
Required columns for library enumeration:

\begin{itemize}
  \item smiles: Chemical structure in SMILES notation

\protocolstep{6}{Create the reactions sheet}

Only required for library enumeration. Define all chemical reactions used during library synthesis with SMARTS/SMIRKS notation\cite{ref34}. SMARTS/SMIRKS should be specified so that each transformation yields a single product. If the same reaction type is used at multiple stages of the synthesis, define each instance as a separate reaction. Table 9 illustrates this with two amide-bond-forming reactions (\texttt{ABF1} and \texttt{ABF2}). A collection of SMARTS/SMIRKS for reactions commonly employed in DEL synthesis is provided in the supplementary information (Supplementary Note~\ref{supp:template-reactions}). Depending on the library setup and the building blocks employed, customization by the user may be required. Before attempting to enumerate an entire library, we recommend a validation of all reaction notations with a representative subset of building blocks.

\protocolstep{9}{Generate the configuration file}

Once your Excel file is complete with all required sheets, generate the YAML configuration file:


\begin{lstlisting}
# Activate the DELT-Hit conda environment
conda activate delt-hit

# Move into the single-stranded example workflow
cd supporting_material/experiments/example-single-stranded

# Generate configuration from Excel template
delt-hit init --excel_path=example-single-stranded.xlsx

# Reuse this config path in the downstream commands
CONFIG_PATH=campaign/config.yaml
\end{lstlisting}
This command creates a YAML configuration file at \texttt{save\_dir/name/config.yaml}, as defined in the \texttt{experiment} sheet.

Expected output:


\begin{lstlisting}
Configuration created at campaign/config.yaml
\end{lstlisting}
CRITICAL STEP: Review the generated YAML file to verify that all information was parsed correctly. This file is used in all downstream steps.

\textbf{Troubleshooting.} While the tool supports some basic input validation it is helpful to check the following if the command fails:

\begin{itemize}
  \item All building blocks are present in the configuration file
  \item Column names match exactly as specified in the tables above
  \item Excel file was saved with the latest changes before running the command
\end{itemize}

\subsection{Phase 2: Sequence processing and demultiplexing • TIMING 30 min - 4 h}
This phase processes raw sequencing reads to identify and count each library member in your selection experiments.


\protocolstep{10}{Configure demultiplexing parameters}

The demultiplexing parameters defined in the Excel file control how reads are processed by Cutadapt. Key parameters include:

\begin{itemize}
  \item \texttt{max\_error\_rate}: Tolerance for sequencing errors (0 = perfect match, 0.1 = \textasciitilde{}10\% errors)
  \item \texttt{indels}: Whether to allow insertions/deletions during barcode matching
\end{itemize}
As noted above, exact matches are recommended for selection barcodes (\texttt{max\_error\_rate = 0}, \texttt{indels = FALSE}) to ensure accurate multiplexing. Constant regions can tolerate higher error rates depending on their length.


\protocolstep{11}{Prepare and execute sequence demultiplexing}

Generate the demultiplexing scripts with its dependencies and execute the analysis:


\begin{lstlisting}
# Generate Cutadapt input files and demultiplexing script
delt-hit demultiplex prepare --config_path=$CONFIG_PATH

# Execute demultiplexing
campaign/demultiplex/cutadapt_input_files/demultiplex.sh
\end{lstlisting}
The demultiplexing process performs:

\begin{itemize}
  \item Adapter detection and trimming: removal of sequencing adapters
  \item Barcode extraction: sequential identification of selection and building block barcodes
  \item Quality filtering: rejection of reads with errors exceeding the defined thresholds
\end{itemize}
The generated shell script runs Cutadapt on the FASTQ file and maps reads to selection and codon identifiers. It produces \texttt{reads\_with\_adapters.gz}, which contains all mapped sequences.

Performance note: Processing speed is approximately 50,000--200,000 reads per second. For a typical dataset with 50--100 million reads, expect 30 min to 2 h of processing time.

Expected outputs:

\begin{itemize}
  \item demultiplex/cutadapt\_output\_files/*.cutadapt.json: Detailed processing statistics for each demultiplexing step
  \item demultiplex/cutadapt\_output\_files/reads\_with\_adapters.gz: Intermediate files with extracted barcodes
\end{itemize}

\protocolstep{12}{Process demultiplexing results and generate count tables}

After demultiplexing, generate the text report and QC figures, then aggregate the results into count tables for each selection:


\begin{lstlisting}
# Generate text-based quality control report
delt-hit demultiplex report --config_path=$CONFIG_PATH

# Generate quality control visualizations
delt-hit demultiplex qc --config_path=$CONFIG_PATH

# Process demultiplexing output and generate count tables
delt-hit demultiplex process --config_path=$CONFIG_PATH

# Also export flattened per-selection count files
delt-hit demultiplex process --config_path=$CONFIG_PATH --as_files=True

# Optional: keep codon-id order instead of sorting by observed counts
# delt-hit demultiplex process --config_path=$CONFIG_PATH --as_files=True --sort_by_counts=False
\end{lstlisting}
These commands:

\begin{itemize}
  \item parse the demultiplexed reads
  \item map barcode combinations to library members
  \item generate count tables for each selection
  \item save the results in a standardized format
\end{itemize}
Expected outputs:

\begin{itemize}
  \item \texttt{selections/[selection\_name]/counts.txt}: Tab-delimited count table with columns:
  \item \texttt{code\_1}, \texttt{code\_2}, ...: Building block indices
  \item \texttt{name}: Selection identifier
  \item \texttt{count}: Number of reads for this compound in this selection
  \item Alternatively, counts can be saved as \texttt{\{selection\_name\}\_counts.txt} with the flag \texttt{--as\_files=True}. To retain codon order rather than sorting by observed counts, use \texttt{--sort\_by\_\allowbreak{}counts=False}.
\end{itemize}

\subsection{Phase 5: Statistical analysis and hit identification • TIMING 10-30 min}
This phase identifies enriched library members by comparing selection conditions using established statistical methods.

\protocolstep{18}{Perform enrichment analysis with statistical methods}

DELT-Hit supports three statistical approaches for identifying enriched compounds. Methods A, B, and C each generate an R script that can be executed directly or adapted further by the user. Methods A and B are designed for evaluation settings with replicates, whereas method C can also be used for experiments without replicates.

A. Simple counts method


\begin{lstlisting}
# Generate R script for counts-based analysis
delt-hit analyse enrichment --analysis_config=analysis.yaml --save_dir=campaign/analysis --name=protein_vs_no_protein --method=counts

# Execute the generated R script
Rscript --vanilla campaign/analysis/counts/protein_vs_no_protein/enrichment_counts.R
\end{lstlisting}
The simple counts method averages counts across replicates within each group and computes a direct enrichment score from the difference between the protein and control groups. It does not provide formal significance testing, but it is useful as a straightforward ranking approach when replicate-based comparisons are being evaluated.

B. edgeR method


\begin{lstlisting}
# Generate R script for edgeR statistical analysis
delt-hit analyse enrichment --analysis_config=analysis.yaml --save_dir=campaign/analysis --name=protein_vs_no_protein --method=edgeR


# Execute the generated R script
Rscript --vanilla campaign/analysis/edgeR/protein_vs_no_protein/enrichment_edgeR.R
\end{lstlisting}
The edgeR method applies RNA-seq-derived statistical modeling with empirical Bayes shrinkage, reports false-discovery-rate-corrected \textit{P} values, and provides normalized count tables for each selection. It requires replicates and is best used as a significance-annotation layer alongside enrichment ranking.

C. Normalized z-score method

\begin{lstlisting}
# Generate R script for normalized z-score analysis
delt-hit analyse enrichment --config_path=campaign/config.yaml --counts=campaign/selections/AG24_15/counts.txt --save_dir=campaign/analysis --name=AG24_15 --method=z_score

# Execute the generated R script
Rscript --vanilla campaign/analysis/z_score/AG24_15/enrichment_z_score.R
\end{lstlisting}
The normalized z-score method computes the per-compound score for an individual selection following Faver et al.\cite{ref42}. Because it does not rely on replicate-based variance estimation, it can also be applied to experiments without replicates.

For all three methods, the tool produces R scripts that can be adapted to more specialized workflows. A comparison of enrichment score rankings for recovery of a previously reported CA9-associated building block by Favalli \cite{ref38} is provided in Supplementary Note~\ref{supp:enrichment-scores-comparison}.

Expected outputs:

\begin{itemize}
  \item \texttt{<method>/hits.csv}: top-ranked compounds
  \item \texttt{<method>/stats.csv}: full results table
  \item \texttt{<method>/enrichment.R}: executable analysis script
\end{itemize}
These files report, for each compound, the enrichment score and, where applicable, method-specific parameters such as log fold change or \textit{P} values.

Interpreting results:

\begin{itemize}
  \item Higher enrichment scores indicate stronger enrichment
  \item Some methods additionally report a log fold change relative to a control; LogFC \textgreater{} 0 corresponds to enrichment relative to the control
  \item FDR \textless{} 0.05 indicates statistically significant enrichment for methods that report adjusted \textit{P} values
  \item High replicate correlation ($R^2 > 0.7$) indicates good experimental consistency
\end{itemize}
CRITICAL STEP: Always examine replicate correlation plots to verify data quality before interpreting hit lists. Poor correlation may indicate technical problems or batch effects.

\textbf{Troubleshooting.} If no hits are identified:

\begin{itemize}
  \item Check that experimental groups are correctly assigned
  \item Verify sufficient sequencing depth (\textgreater{}100 reads per compound for reliable statistics)
  \item Consider adjusting FDR threshold for exploratory analysis
  \item Examine correlation plots for replicate consistency issues
\end{itemize}

\subsection{Phase 6: Full library enumeration and machine learning representations • TIMING 1 h - 8 h}
This phase performs full-library enumeration and generates molecular representations for downstream machine-learning applications. These steps are optional.

\protocolstep{19}{Enumerate the full library}

Enumerate all library members for downstream machine-learning tasks:

\begin{lstlisting}
delt-hit library enumerate --config_path=$CONFIG_PATH
\end{lstlisting}

\protocolstep{20}{Calculate molecular properties for the full library}

Calculate molecular properties for all library members:

\begin{lstlisting}
delt-hit library properties --config_path=$CONFIG_PATH
\end{lstlisting}

\protocolstep{21}{Generate molecular representations for machine learning}

Create standardized chemical representations compatible with common machine-learning frameworks:


\begin{lstlisting}
# Morgan fingerprints for similarity analysis
# ~600-1000 compounds/s
delt-hit library represent --method=morgan --config_path=/path/to/config.yaml

# BERT embeddings for deep learning applications
# ~600-1000 compounds/s
delt-hit library represent --method=bert --config_path=/path/to/config.yaml
\end{lstlisting}
Available representation methods:

\begin{itemize}
  \item morgan: Morgan circular fingerprints (2048-bit vectors) for similarity searching and clustering
  \item bert: Transformer-based molecular embeddings (768-dimensional vectors) for deep-learning applications
\end{itemize}
Expected outputs:

\begin{itemize}
  \item representations/morgan.npz: Sparse matrix of Morgan fingerprints
  \item representations/bert.npz: Dense matrix of BERT embeddings
\end{itemize}
Note: These representations are compatible with scikit-learn, PyTorch, and TensorFlow.
